# 轻量契约生成器设计（idlc）

> 状态：草案（待评审）
> 范围：`rk3568-automotive-platform` 的 `com` 绑定层之上的服务封装
> 相关文档：`docs/VehicleStatus_Contract.md`（现有手写契约，第 7 节标注"代码生成 未开始"）

## 1. 背景

当前每新增一个 SOME/IP 服务，都要手写四个文件：

| 文件 | 现状（以 VehicleStatus 为例） | 性质 |
| --- | --- | --- |
| `xxx_protocol.h` | service/instance/method ID、`Errc`/`OtaState` 枚举、编解码函数声明 | 纯机械 |
| `xxx_protocol.cpp` | `AppendU16/32/64/String`、`Read*` | 纯机械（且每个服务重复一份） |
| `xxx_proxy.cpp` | 组包 → `BindHandle::SendRequest(id, req, limit)` → 读 `Errc` → 解包 | 模式固定 |
| `xxx_service_skeleton.cpp` | `RegisterMethodHandler(id, lambda)` → 解包 → 调业务 → 组包 | 模式固定 |

`docs/VehicleStatus_Contract.md` 已经把服务 ID、编码规则、四个方法的字段序列写清楚了，但这份契约只能靠人读，改一处就要手工同步四处代码。`docs/VehicleStatus_Contract.md` 第 7 节也明确写着"代码生成 未开始"。

而 `com` 层已经把可变部分收敛了：

```
应用 / 业务服务        VehicleStatusService（手写，不生成）
        |
生成层（本设计）        VehicleStatusProxy / VehicleStatusServiceSkeleton / codec
        |
绑定层（稳定抽象）      com::proxy::BindHandle / com::skeleton::BindSkeleton
        |
运行时（稳定抽象）      com::BindRuntime / vsomeip 实现
```

生成器的目标就是把"生成层"自动化。

## 2. 目标

1. 契约用 YAML 描述，作为 service/instance/method/event ID、字段序列、枚举、错误码的**唯一真源**。
2. 从契约生成 Proxy、Skeleton、编解码、ID 头文件，**与现有手写实现字节级兼容**，现有调用点不改一行。
3. 生成物可重复生成、可校验（`--check`），能在 CMake 里自动触发。
4. 生成器本身零第三方依赖（除 PyYAML），能在 Ubuntu 18.04 + Python 3.6.9 上跑。

## 3. 非目标

- 不做 ara::com 的 ARXML 全量代码生成（不生成接口类继承体系、不做 E2E/安全、不做服务部署清单）。
- 不生成业务实现，也不生成 `BindHandle` / `BindSkeleton` / `BindRuntime` 抽象。
- 不改现有二进制线格式。现有对端（PC 侧 someip 工具、`config/vehicle_status-*.json`）必须继续能对上。
- 首版不支持嵌套 struct、变长数组、可选字段；这些等第二个服务有需求再加。

## 4. 契约格式

### 4.1 位置与命名

```
contracts/
  vehicle_status.yaml
```

一个文件一个服务。文件名用 snake_case，与生成物前缀一致。

### 4.2 顶层结构

```yaml
package: vehicle_status          # C++ 命名空间，也是生成物文件名前缀
service: VehicleStatus           # 类名前缀，生成 VehicleStatusProxy / VehicleStatusServiceSkeleton
service_id: 0x6100
instance_id: 0x0001
version: {major: 1, minor: 0}
```

### 4.3 encoding：固化的线格式约定

```yaml
encoding:
  endianness: big                # 与现有实现一致，固定大端
  string: {length: u32}          # u32 长度 + UTF-8 原始字节
  error: {name: Errc, type: u32, first_field: true}
```

这三条直接决定生成代码能不能和现有实现对上，**不提供关闭选项**。将来要换编码就换 `encoding` 版本号并保留旧模板，不在原地改。

### 4.4 类型系统

| 契约类型 | C++ 类型 | 编码 | 备注 |
| --- | --- | --- | --- |
| `u8` / `u16` / `u32` / `u64` | `std::uint8_t` 等 | 大端定长 | |
| `i8` / `i16` / `i32` / `i64` | 有符号定长 | 大端补码 | 首版可不实现 |
| `bool` | `bool` | 1 字节 0/1 | |
| `string` | `std::string` | `u32` 长度 + 字节 | 现有格式 |
| `<EnumName>`（在 `enums` 里声明） | 生成的 `enum class` | 底层类型由枚举声明决定 | |
枚举名直接当类型名用（`type: OtaState`），**不要写 `enum:OtaState`**：YAML 的 flow mapping 里冒号未加引号会被解析器拒绝（PyYAML 报 `found unexpected ':'`，实测）。

| `bytes` | `std::vector<std::uint8_t>` | `u32` 长度 + 字节 | 与 string 同构 |

枚举/错误码声明：

```yaml
enums:
  Errc: {type: u32, values: {Success: 0, InvalidArgument: 1, NotFound: 2, Busy: 3,
                             InternalError: 4, NotReady: 5, VerifyFailed: 6,
                             InstallFailed: 7, RollbackFailed: 8}}
  OtaState: {type: u8, values: {Idle: 0, Downloading: 1, Verifying: 2, Installing: 3,
                                ReadyToSwitch: 4, Rebooting: 5, Success: 6,
                                Failed: 7, Rollback: 8}}
```

生成 `enum class OtaState : std::uint8_t`，枚举名加 `k` 前缀：`OtaState::kIdle`（与现有代码风格一致）。

### 4.5 方法与事件

```yaml
methods:
  - name: GetStatus
    id: 0x0001
    request: []
    response:
      - {name: version, type: string}
      - {name: current_slot, type: string}
      - {name: ota_state, type: OtaState}

events:
  - name: OtaStateChanged
    id: 0x8001
    event_group: 0x0001
    payload:
      - {name: ota_state, type: OtaState}
      - {name: percent, type: u32}
```

首版 `events` 只生成常量和 codec，不生成 `Subscribe` 封装（要等 `SubscribeEvent/OfferEvent` 那条线合进来）。

## 5. 生成物

### 5.1 文件清单

每个服务 5 个文件 + 1 个 CMake 片段：

```
generated/vehicle_status/
  vehicle_status_ids.h          # service/instance/method/event ID、enum class
  vehicle_status_codec.h        # Encode/Decode 声明 + 类型别名
  vehicle_status_codec.cpp      # Encode/Decode 实现
  vehicle_status_proxy.h/.cpp   # 与现有签名一致的代理类
  vehicle_status_skeleton.h/.cpp# Register(BindSkeleton&) 封装
  CMakeLists.txt                # OBJECT 库 gen_vehicle_status
```

顶层 `generated/CMakeLists.txt` 由生成器一并产出，`src/CMakeLists.txt` 里 `add_subdirectory(generated)`。

### 5.2 文件头

```cpp
// @generated by tools/idlc/idlc.py from contracts/vehicle_status.yaml
// DO NOT EDIT. Run `python3 tools/idlc/idlc.py generate contracts/vehicle_status.yaml` to regenerate.
```

### 5.3 codec

每个方法四个函数，命名固定：

```cpp
void EncodeGetStatusRequest(std::vector<std::uint8_t>& out);
bool DecodeGetStatusRequest(const std::vector<std::uint8_t>& in, std::size_t& pos);
void EncodeGetStatusResponse(std::vector<std::uint8_t>& out, const Errc& errc,
                             const std::string& version, /* ... */ const OtaState& ota_state);
bool DecodeGetStatusResponse(const std::vector<std::uint8_t>& in, std::size_t& pos,
                             Errc& errc, std::string& version, /* ... */ OtaState& ota_state);
```

约定：

- 响应编码函数第一个参数永远是 `errc`，写在最前面（对应 `encoding.error.first_field`）。
- 解码函数返回 `bool`，`pos` 由调用方持有，失败时不保证 `pos` 不变（调用方应丢弃整条消息）。
- 空请求/空响应仍生成函数（空实现或只写 error），保持调用点形状一致。
- 基础 `AppendU16/AppendU32/AppendU64/AppendString/Read*` 从 `vehicle_status_protocol.cpp` 上提到共享的 `src/com/codec.h/.cpp`，生成代码只依赖共享实现，不再每个服务复制一份。

### 5.4 proxy

生成的头与现有调用点兼容：

```cpp
class VehicleStatusProxy {
public:
    explicit VehicleStatusProxy(com::proxy::BindHandle& handle);

    Errc GetStatus(std::string& version, std::string& current_slot, OtaState& ota_state);
    Errc StartUpdate(const std::string& version, std::uint64_t package_size,
                     const std::string& sha256, std::string& update_id);
    Errc GetProgress(const std::string& update_id, OtaState& ota_state,
                     std::uint32_t& percent, std::string& detail);
    Errc Rollback();

private:
    com::proxy::BindHandle& handle_;
};
```

生成体固定为：

```cpp
Errc VehicleStatusProxy::GetStatus(std::string& version, std::string& current_slot,
                                   OtaState& ota_state) {
    std::vector<std::uint8_t> request;
    EncodeGetStatusRequest(request);
    auto result = handle_.SendRequest(kMethodGetStatus, request, std::chrono::seconds(5));
    if (!result) {
        return Errc::kInternalError;
    }
    const std::vector<std::uint8_t>& data = result.Value();
    std::size_t pos = 0;
    Errc errc = Errc::kInternalError;
    if (!DecodeGetStatusResponse(data, pos, errc, version, current_slot, ota_state)) {
        return Errc::kInternalError;
    }
    return errc;
}
```

超时（`std::chrono::seconds(5)`）作为契约字段 `method_timeout_ms` 可选覆盖，默认 5000。

### 5.5 skeleton

```cpp
class VehicleStatusServiceSkeleton {
public:
    explicit VehicleStatusServiceSkeleton(VehicleStatusService& service);
    void Register(com::skeleton::BindSkeleton& bind);
private:
    VehicleStatusService& service_;
};
```

生成体会保留现有模式：

```cpp
void VehicleStatusServiceSkeleton::Register(com::skeleton::BindSkeleton& bind) {
    bind.RegisterMethodHandler(kMethodGetStatus,
        [this](const std::vector<std::uint8_t>& request, std::vector<std::uint8_t>& response) {
            std::size_t pos = 0;
            if (!DecodeGetStatusRequest(request, pos)) {
                EncodeGetStatusResponse(response, Errc::kInvalidArgument, {}, {}, OtaState::kIdle);
                return;
            }
            std::string version;
            std::string current_slot;
            OtaState ota_state = OtaState::kIdle;
            const Errc errc = service_.GetStatus(version, current_slot, ota_state);
            EncodeGetStatusResponse(response, errc, version, current_slot, ota_state);
        });
    /* ... */
}
```

注意：现有手写实现**只在 `errc == kSuccess` 时**才追加载荷（`vehicle_status_skeleton.cpp:26-30`）。生成器的默认行为必须与此一致（`encoding.error.payload_on_success_only: true`），否则线格式变了。

### 5.6 ids 头

```cpp
namespace vehicle_status {
constexpr std::uint16_t kServiceId = 0x6100;
constexpr std::uint16_t kInstanceId = 0x0001;
constexpr std::uint16_t kMethodGetStatus = 0x0001;
constexpr std::uint16_t kEventOtaStateChanged = 0x8001;
constexpr std::uint16_t kEventGroupOtaStateChanged = 0x0001;
}
```

## 6. 映射规则

| 契约元素 | 生成物 | 规则 |
| --- | --- | --- |
| `service_id` | `kServiceId` | 原样 |
| `methods[].id` | `kMethod<Name>` | 名字转 PascalCase |
| `events[].id` | `kEvent<Name>` / `kEventGroup<Name>` | |
| `request[]` | `Encode/Decode<Name>Request` | 按字段顺序 |
| `response[]` | `Encode/Decode<Name>Response` | `errc` 强制第一 |
| `enum` | `enum class <Name> : <type>` | 值名加 `k` 前缀 |
| `event.payload[]` | `Encode/Decode<Name>Event` | 无 errc 前缀 |

## 7. 工具实现

### 7.1 命令行

```bash
python3 tools/idlc/idlc.py generate contracts/vehicle_status.yaml --out generated/
python3 tools/idlc/idlc.py check    contracts/vehicle_status.yaml --out generated/
python3 tools/idlc/idlc.py dump     contracts/vehicle_status.yaml    # 调试：打印解析后的模型
```

- `generate` 写文件；内容未变化时不改 mtime（避免无谓重建）。
- `check` 生成到临时目录后逐个比对，有差异 exit 1 并打印 `diff`。
- 退出码：0 成功，1 契约/校验/差异失败，2 参数错误。

### 7.2 实现约束

- **Python 3.6.9**（VM 上的版本）：不能用 `dataclasses`、`typing.List[str]` 下标写法、`f"{x=}"`、海象运算符。用 `collections.namedtuple` 或普通类。
- **只依赖 PyYAML 3.12**（已装）；不用 jinja2（未装，且 `pip` 不可用）。模板用显式字符串拼接函数，不用模板引擎。
- 代码结构：

```
tools/idlc/
  idlc.py          # CLI 入口
  model.py         # 契约解析 + 校验（返回 ServiceModel）
  cpptypes.py      # 契约类型 -> C++ 类型/编码调用的映射表
  emit_ids.py
  emit_codec.py
  emit_proxy.py
  emit_skeleton.py
  emit_cmake.py
```

### 7.2.1 解释器与依赖（VM 实测）

VM 是 Ubuntu 18.04.6 / Python 3.6.9，`ensurepip` 和 `pip` 都不存在，直接 `python3 -m venv` 会失败。已验证可用的做法（无需 root）：

```bash
python3 -m venv --without-pip --system-site-packages ~/venv/idlc
~/venv/idlc/bin/python -c "import yaml; print(yaml.__version__)"   # 3.12
```

`--without-pip` 绕开缺失的 `ensurepip`，`--system-site-packages` 让 venv 直接复用 `/usr/lib/python3/dist-packages` 里的 PyYAML 3.12。

代价：没有 pip，无法在 venv 内固定 PyYAML 版本。要装包必须先 `sudo apt update && sudo apt install python3-venv python3-pip`（需密码，当前 `apt` 缓存为空）。

CMake 里必须用显式解释器，不要依赖 `PATH`：

```cmake
set(IDLC_PYTHON "$ENV{HOME}/venv/idlc/bin/python" CACHE FILEPATH "interpreter for tools/idlc")
```

### 7.3 契约校验（`check` 前先跑）

- ID 唯一且非 0，`service_id`/`instance_id` 不与其他契约重复（扫描 `contracts/*.yaml`）。
- 方法/事件 ID 不冲突，事件 ID 落在 0x8000 以上。
- 类型引用存在；枚举值在底层类型范围内且不重复。
- 字段名 snake_case、方法名 PascalCase；`errc` 不能出现在 `request` 里。
- `encoding` 版本已知（未知版本直接失败，避免静默按新规则生成）。

## 8. 构建集成

### 8.1 生成物是否入库

建议**入库**。理由：CI/板端构建环境不一定有 Python + PyYAML；代码评审时能看到生成结果；`--check` 保证入库内容与契约一致。

代价是被生成文件也进 diff。用 `@generated` 头 + 约定"只 review 契约"，可接受。

### 8.2 CMake

`generated/CMakeLists.txt` 由生成器产出：

```cmake
add_library(gen_vehicle_status OBJECT
    vehicle_status/vehicle_status_codec.cpp
    vehicle_status/vehicle_status_proxy.cpp
    vehicle_status/vehicle_status_skeleton.cpp
)
target_include_directories(gen_vehicle_status PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})
target_link_libraries(gen_vehicle_status PUBLIC com)
```

可选（推荐）：用 `add_custom_command` 把生成挂到构建图，改契约自动重生成：

```cmake
add_custom_command(
    OUTPUT ${CMAKE_CURRENT_BINARY_DIR}/idlc.stamp
    COMMAND python3 ${PROJECT_SOURCE_DIR}/tools/idlc/idlc.py generate
            ${PROJECT_SOURCE_DIR}/contracts --out ${PROJECT_SOURCE_DIR}/generated
    COMMAND ${CMAKE_COMMAND} -E touch ${CMAKE_CURRENT_BINARY_DIR}/idlc.stamp
    DEPENDS ${PROJECT_SOURCE_DIR}/contracts/vehicle_status.yaml
            ${PROJECT_SOURCE_DIR}/tools/idlc/idlc.py
)
```

另有 `idlc_check` 目标，CI 里跑 `cmake --build build --target idlc_check`。

## 9. 测试策略

1. **字节级对照**（最关键）：同一组入参，手写 `AppendString/AppendU32` 序列与生成 codec 输出的 `std::vector<std::uint8_t>` 逐字节比对；解码同理。测试用 `ctest` 或一个 `tests/codec_golden.cpp`，期望值直接写十六进制数组。
2. **快照测试**：对 `contracts/vehicle_status.yaml` 生成结果做文本快照（golden 文件），生成器改动时人工确认 diff。
3. **端到端**：`apps/vehicle_status_client` 连 `vehicle_status_service`，四个方法都能通；切换前后抓包比对 SOME/IP payload。
4. **漂移检测**：`idlc check` 挂 pre-commit 与 CI。

## 11. 风险与未决问题

1. **契约与手写实现漂移**：首版两份并存时最容易出问题，靠 9.1 的字节对照 + `--check` 控制；不通过不进入第 4 步。
2. **现有 proxy 签名是"返回 Errc + 出参引用"**，如果生成器为了好看改成 struct 返回值，调用点和错误语义都会变。首版必须沿用出参风格。
3. **`payload_on_success_only` 这个细节**：现有 skeleton 只在成功时追加字段（`vehicle_status_service_skeleton.cpp:26`），漏掉就是线格式变更。契约里显式写、生成器里单测。
4. **events 与上游 `SubscribeEvent/OfferEvent` 的合并顺序**：那三处接口改动目前还在未提交/未合并状态，生成器先只产常量与 codec，等接口稳定再接。
5. **Python 3.6 + PyYAML 3.12 的兼容面**：生成器要在 VM 上直接跑，不能引入需要新 pip 包的依赖。
6. **多服务共享基础类型**：`string` 长度类型、字节序一旦改，所有已部署对端都受影响。放到 `encoding` 版本里，不在原契约上改。
7. **`config/vehicle_status-*.json` 与契约重复**：vsomeip 配置里的 service/instance/eventgroup ID 与契约重复，容易漂。可选第二期让生成器一并产出这两个 json（本设计不做，留接口）。
8. **生成代码可读性**：每个方法约 40~60 行样板，调试时 `gdb` 栈会多一层 `Encode*/Decode*`。可接受，但 codec 函数加 `inline` 与清晰命名。

                             Errc& errc, std::string& version, std::string& current_slot,
